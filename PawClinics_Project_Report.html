Overview page. Shows a time-based greeting, stat cards (branches count, staff count, assigned branch name), quick action cards, and a "Recent Staff" table showing the first 5 members. BranchesList src/pages/Branches/BranchesList.tsx

Paginated table of all clinic branches. Columns: Title (Main badge), Phone, Address, Services count, Days open (count of working hour entries), Tags (first 3 + overflow badge). Shows "New Branch" and edit buttons only if user has the relevant permissions. Success message is passed via React Router location state when redirected from create/edit.

BranchForm src/pages/Branches/BranchForm.tsx

Reusable form shared by CreateBranch and EditBranch. Divided into four sections:

  • Basic Info — title (required), description textarea, logo URL with live preview, isMainBranch + isActive toggles
  • Contact & Location — phone, City/Area/Street (combined into a single address string on submit), MapPicker for lat/lng
  • Working Hours — 7-day table, each day has enable toggle + start/end time pickers
  • Tags & Services — chip input (Enter/comma adds tag, Backspace removes last), service IDs text field

StaffList src/pages/Staff/StaffList.tsx

Paginated staff table with a debounced (300ms) text search and a branch filter dropdown. Columns: Name (avatar initials + full name + ID), Email, Role badge, Assigned branches, Experience years, Joined date. Roles and branches for filters are only loaded if the user has the corresponding read permissions — failures show warning banners instead of blocking the page.

// Returns true if staff.role.name contains "owner" (case-insensitive)

// 1. Returns true if isPrivilegedClinicRole(staff)

// 3. Each entry can be a string OR an object — checks .token first,

Auth Context src/context/ClinicAuthContext.tsx

State & Context Value

// State shape inside provider:
interface ClinicAuthState {
  staff:           ClinicStaff | null;
  token:           string | null;
  clinicId:        string | null;
  branchId:        string | null;
  isAuthenticated: boolean;
  isLoading:       boolean;   // true during localStorage hydration
}

// Exposed via useClinicAuth():
interface ClinicAuthContextValue extends ClinicAuthState {
  login:  (email: string, password: string) => Promise<void>;
  logout: () => void;
}

Login Flow

1. User submits email + password on /login
2. context.login() → clinicAuthService.login()
3. POST /clinic/api/auth/login
   Response: { token, staff, branches }
4. Extract clinicId & branchId from staff.branches[0]
5. Store to localStorage:
   clinicStaffToken, clinicStaff, portalClinicId, portalBranchId
6. Update context state → isAuthenticated = true
7. Navigate to /dashboard

Logout Flow

1. User clicks logout in ClinicSidebar
2. context.logout()
3. clinicAuthService.logout() → clear all 4 localStorage keys
4. Reset context state → isAuthenticated = false
5. Navigate to /login

App Hydration (on first load)

1. ClinicAuthProvider mounts → isLoading = true
2. useEffect runs getStoredAuth() synchronously
3. If token + staff found → restore full auth state
4. If missing or corrupted → clear state, stay logged out
5. isLoading = false
6. ProtectedRoute reads isLoading + isAuthenticated to decide render

Auto-logout on 401

If any API call returns HTTP 401, clinicApi clears localStorage and performs a hard redirect to /login — no React state update needed.

├─ /login                → <Login />  (public — auto-redirects if authenticated)
│

      ├─ /staff/create    → <CreateStaff />
      ├─ /staff/:id       → <EditStaff />
      └─ *                → <NotFound />
Vercel SPA Routing: A vercel.json catch-all rewrite redirects all non-API paths to /index.html, preventing 404 errors on browser refresh or direct URL access.

Permission Decision Flow

hasClinicPermission(staff, 'clinic-branches.create')
         │
         ▼
  isPrivilegedRole?  ──→  YES ──→  return true  (owner bypasses all)
         │
         NO
         ▼
  check staff.role.permissions[]
  check staff.permissions[]
         │
  for each permission entry:
    if string → normalise + compare
    if object → try .token, .slug, .name, .title, .key, .code, .permission
         │
  match found? ──→  YES ──→  return true
         │
         NO ──→  return false
